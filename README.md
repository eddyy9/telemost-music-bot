# Telemost Music Bot

Музыкальный бот для Яндекс Телемоста. Заходит на встречу отдельным участником
и играет звук с YouTube. Управление — из терминала.

## Portable-версия для пользователя

Готовая сборка находится в `dist\TelemostMusicBot-portable.zip`. Её можно
передать на другой компьютер с Windows 10/11: распаковать архив и запустить
`TelemostMusicBot.exe`. Python, зависимости, ffmpeg и Chromium уже находятся
внутри. В приложении есть `guide` для первого запуска, `help` со всеми
командами и `selftest` для быстрой проверки комплектации.

Отдельно всё равно требуется **VB-Audio Virtual Cable**: это системный драйвер,
поэтому его нужно один раз установить от имени администратора и перезагрузить
Windows. Краткая инструкция для получателя лежит в `PORTABLE_README.txt`.

## Как это работает

У Телемоста нет API для звука, поэтому «бот» — это настоящий Chrome, который
заходит на встречу гостем. Питон-скрипт качает звук с YouTube и пишет его в
виртуальный аудиокабель, а Chrome считает этот кабель своим микрофоном.

```
YouTube ──yt-dlp──> ffmpeg ──PCM──> [громкость] ──> CABLE Input
                                                        │
                                                   (драйвер VB-Audio)
                                                        │
                                                   CABLE Output ──> Chrome (бот) ──> Телемост
```

Твой обычный микрофон при этом не трогается — ты сидишь в звонке как обычно,
бот сидит рядом отдельным участником.

## Установка из исходников (один раз)

1. **Python 3.10+** с [python.org](https://www.python.org/downloads/). При установке
   обязательно галочка **«Add python.exe to PATH»**.
2. Запусти **`setup.bat`** — поставит зависимости и браузер.
3. **VB-Audio Virtual Cable** — [vb-audio.com/Cable](https://vb-audio.com/Cable/).
   Распаковать, запустить `VBCABLE_Setup_x64.exe` **от имени администратора**,
   перезагрузиться.

> Сообщения в `.bat`-файлах намеренно на английском: cmd.exe ломается на
> кириллице в батниках (начинает выполнять обрывки строк как команды).
> Весь русский — в Python, там с кодировками всё в порядке.

> Папка лежит на рабочем столе внутри OneDrive. После `setup.bat` в ней появится
> `.venv` — это тысячи файлов, которые OneDrive полезет синхронизировать.
> Если начнёт тормозить, перенеси всю папку куда-нибудь вроде `C:\telemost-bot`
> — путь нигде не зашит, работать будет откуда угодно.

Проверка: в «Параметры звука → Дополнительные параметры звука» должны появиться
устройства `CABLE Input` (воспроизведение) и `CABLE Output` (запись).

## Запуск

Двойной клик по **`start.bat`**.

```
bot> join https://telemost.yandex.ru/j/12345678901234
bot> play https://www.youtube.com/watch?v=dQw4w9WgXcQ
bot> vol 60
```

### Команды

| Команда | Что делает |
|---|---|
| `join <ссылка>` | подключить бота к встрече |
| `play <ссылка\|текст>` | играть ролик или плейлист; текст — найдёт поиском по YouTube |
| `play <ссылка> @40:00` | начать сразу с сороковой минуты |
| `add <ссылка\|текст>` | дописать в конец списка |
| `seek 40:00` | перемотать; понимает `1:12:30`, `+60`, `-30` |
| `pos` | сколько уже отыграло |
| `resume` | продолжить с места, где остановились в прошлый раз |
| `pause` | пауза / снять с паузы |
| `next` | следующий трек |
| `stop` | остановить и очистить список |
| `vol <0-300>` | громкость в процентах, 100 = как есть |
| `+` / `-` | громкость ±10 |
| `norm [on\|off]` | выравнивание громкости треков, по умолчанию включено |
| `test` | проиграть свой сигнал мимо интернета — проверка тракта вывода |
| `ym [ссылка]` | открыть Яндекс.Музыку и увести её звук в звонок |
| `ym off` | закрыть это окно, звук вернётся на место |
| `list` | что играет и что дальше, со значками состояния |
| `stats` | что бот реально отдаёт в звонок: битрейт, кодек, стерео, потери пакетов |
| `dev` / `dev <n>` | список устройств вывода / выбрать вручную |
| `guide` | пошаговая инструкция для первого запуска |
| `diag` | полная диагностика Windows, кабеля и браузера |
| `selftest` | быстрая офлайн-проверка компонентов portable-сборки |
| `quit` | выход |

## Как бот понимает ссылки

Когда копируешь ссылку с YouTube при открытом плейлисте, в буфер попадает
`watch?v=XXX&list=PLYYY&index=7`. Такая ссылка — это **ролик**, и бот добавит
именно его, а про плейлист скажет отдельной строкой.

Нужен весь список — дай явную ссылку `youtube.com/playlist?list=...`.

## Перемотка длинных роликов

Двухчасовой эмбиент можно слушать не с начала:

```
bot> play https://youtu.be/skellige @40:00
bot> seek 1:12:30
bot> seek +60
bot> pos
   Skellige Ambient — 1:13:30 из 2:00:45
```

Работает это так. Обычное прослушивание с начала всегда идёт **через yt-dlp** —
проверенный путь, он переживает всё, что YouTube делает с прямыми ссылками.

Прямая ссылка на поток берётся только ради перемотки: по ней ffmpeg просит у
сервера кусок с нужной минуты и получает его сразу, а через трубу пришлось бы
скачать и выбросить всё начало. Если YouTube оборвёт прямое соединение (в
России это обычное дело), бот об этом скажет, пометит трек и следующей
попыткой пойдёт через yt-dlp — медленнее, но надёжно.

**Бот запоминает, где вы остановились** в роликах длиннее 15 минут. Включишь
ту же ссылку завтра — скажет `в прошлый раз остановились на 40:12`, и команда
`resume` продолжит оттуда. Метки лежат в `positions.json` рядом с ботом,
доигранные до конца стираются сами.

## Очередь

После `add` бот в фоне проверяет каждый трек, не скачивая: доступен ли,
какая длительность. О недоступных сообщает **сразу**, а не когда до них
дойдёт очередь. В `list` у каждого трека значок:

| Значок | Что значит |
|---|---|
| `.` | ждёт проверки |
| `+` | проверен, готов |
| `>` | играет сейчас |
| `x` | недоступен или не сыграл, причина строкой ниже |

Если скачивание сорвалось, бот делает три попытки с паузой — сбои часто
разовые. Только после этого помечает трек крестиком и идёт дальше.

Вся история пишется в **`history.log`** рядом с ботом: что добавили, что
начали, сколько сыграло, что упало и почему. Если вечер не задался,
ответ будет там.

## Первый заход: что проверить руками

После `join` откроется окно Chrome. Автоклик по кнопкам входа — вещь хрупкая,
Яндекс регулярно меняет вёрстку, так что окно специально видимое:

1. Если бот не вошёл сам — **дожми кнопку «Присоединиться» мышкой**. На звук это
   никак не влияет.
2. **Выключи камеру бота**, если она включилась.
3. Открой настройки Телемоста в окне бота и убедись, что микрофон —
   **`CABLE Output (VB-Audio Virtual Cable)`**. Скрипт выставляет его сам через
   патч `getUserMedia`, но если Яндекс что-то поменял — выстави руками.
4. Впусти бота из комнаты ожидания, если она включена.

## Яндекс.Музыка

```
bot> ym
  открываю... первый раз надо будет войти в Яндекс, дальше запомнит
  звук страницы уходит в CABLE Input (VB-Audio Virtual Cable)
  жми play в открывшемся окне — музыку услышат все в звонке
  закончите — набери ym off, и всё вернётся само
```

Можно сразу со ссылкой: `ym https://music.yandex.ru/album/123/track/456`.

Свой плеер бот при этом глушит сам — вдвоём в один кабель они не поместятся.

**Как это устроено.** Обычно вывод приложения переключают в микшере Windows, и
эту настройку потом приходится возвращать руками (а если забыть — на следующий
день сидишь в тишине и не понимаешь почему). Здесь то же самое делается
**изнутри страницы** методом `setSinkId`. Систему никто не трогает, поэтому
`ym off` возвращает всё мгновенно и без следов.

Окно открывается в профиле бота, так что вход в Яндекс запомнится с первого раза.

### Если не сработало

Браузер имеет право не дать переключать вывод звука. Тогда бот честно скажет
`браузер не дал переключить вывод` и назовёт причину. В этом случае остаётся
ручной путь:

1. Включи трек в Яндекс.Музыке (пока не играет, Windows её не покажет).
2. Параметры → Система → Звук → **Микшер громкости**.
3. Приложению поставь вывод **`CABLE Input`**.
4. В боте `stop`.
5. **Наигрались — верни «По умолчанию» там же.** Windows запоминает это за
   приложением, само не откатится.

### Что нужно помнить в любом случае

**Ты сам музыку слышать не будешь** — она ушла в кабель. Лечится один раз:
Панель управления → Звук → «Запись» → `CABLE Output` → Свойства → вкладка
«Прослушать» → галочка «Прослушивать с данного устройства» → выбрать наушники.
Работает и для музыки бота тоже, можно оставить насовсем. Только не в колонках,
иначе микрофон поймает музыку и получится каша.

**Бот про эти треки ничего не знает** — `list`, `next`, `pos` на них не
действуют, для него это поток извне. Переключаешь сам в окне.

Тем же способом можно транслировать что угодно — просто дай `ym` ссылку на
любую страницу со звуком.

## Не слышно бота? Запусти `diag.bat`

Это главный инструмент отладки. Он по очереди проверяет три места, где всё
обычно ломается, и выдаёт готовый список того, что чинить:

1. **Запреты Windows** — читает реестр и говорит, разрешён ли микрофон
   классическим приложениям.
2. **Устройства** — печатает все входы и выходы, отдельно проверяя,
   что `CABLE Input` есть среди воспроизведения, а `CABLE Output` — среди записи.
3. **Браузер** — открывает настоящий домен Телемоста (страницу подменяет
   локально) и пробует взять микрофон. Это важно: проверяется ровно то
   разрешение, которое спрашивает настоящий Телемост, а не абстрактное.

Расшифровка ошибок делается за тебя: `NotAllowedError` со словом *system*
означает запрет Windows, без него — заблокированное разрешение для сайта,
`NotFoundError` — браузер не видит микрофонов вообще, `NotReadableError` —
устройство занято другой программой.

### Самая частая причина

**Параметры → Конфиденциальность и защита → Микрофон.** Нужны обе галочки:
«Доступ к микрофону» и, ниже, **«Разрешить классическим приложениям доступ к
микрофону»**. Вторую почти все пропускают, а без неё браузер получает отказ
ещё до того, как покажет запрос.

Вторая по частоте — `CABLE Output` отключён во вкладке **«Запись»**
(Параметры → Система → Звук → Дополнительные параметры звука). Правый клик →
«Включить».

Если разрешение однажды заблокировали вручную — удали профиль браузера, он
хранит решения по сайтам. Лежит он в
`%LOCALAPPDATA%\telemost-music-bot\chrome-profile` (вставь этот путь в адресную
строку проводника). Специально не в папке бота: она внутри OneDrive, а профиль
Chromium — это тысячи мелких файлов, синхронизация их портит.

## Если что-то не так

**Бота слышно, но музыка булькает / пропадает**
Это эхоподавление и шумодав Телемоста жуют музыку. Скрипт их отключает патчем,
но если Телемост обновился — открой DevTools в окне бота (F12) и посмотри лог
`[bot] getUserMedia -> кабель:`. Если там `НЕ НАЙДЕН` — кабель не подхватился.

**`TargetClosedError: Target page, context or browser has been closed`**
Браузер стартует и тут же умирает. Почти всегда виноват один из флагов
запуска: разные сборки Chromium и Edge переваривают их по-разному. Бот сам
пробует четыре набора от полного до пустого, так что просто запусти ещё раз.
Чтобы узнать конкретный флаг — `diag.bat`, она перебирает их по одному и
называет виновника поимённо.

**Бота вообще не слышно**
Проверь три вещи: (1) в терминале написано `Звук пойдёт в: CABLE Input...`,
(2) в Телемосте у бота выбран микрофон `CABLE Output`, (3) бот не замьючен.

**`Виртуальный кабель не найден`**
VB-Cable не установлен или не было перезагрузки. Или посмотри `dev` и выбери
устройство вручную: `dev 7`.

**Звук глуховатый**
Так и будет. WebRTC гоняет голосовой Opus на ~32 кбит/с моно — это физический
предел канала, а не баг скрипта.

**Тишина вместо музыки**

Порядок действий:

1. Набери **`test`** — бот проиграет свой сигнал мимо интернета и yt-dlp.
   Слышно в звонке → тракт цел, дело в скачивании, иди к пункту 2.
   Не слышно → проблема в выводе звука, запускай `diag.bat`.
2. Закрой бота и запусти **`update.bat`**.

Начиная с этой версии бот сам объясняет, что сломалось: если трек оборвался
почти сразу, он показывает последние строки от yt-dlp и ffmpeg и говорит,
что с этим делать. Раньше он в такой ситуации просто молчал — моя недоработка.

**`play` ругается на YouTube**
Запусти **`update.bat`**. YouTube ломает yt-dlp примерно раз в месяц, лечится
обновлением. Повторный `setup.bat` тут не поможет: версии в `requirements.txt`
не закреплены, pip видит уже установленный пакет и считает дело сделанным.
Обновить всё остальное разом (нужно редко):
`.venv\Scripts\python.exe -m pip install -U -r requirements.txt`
и следом `.venv\Scripts\python.exe -m playwright install chromium`.

## Файлы

- `bot.py` — терминальный интерфейс
- `audio.py` — плеер: yt-dlp → ffmpeg → виртуальный кабель, громкость
- `browser.py` — заход в Телемост, патч `getUserMedia`
- `diag.py` — диагностика микрофона (запускается через `diag.bat`)
- `update.bat` — обновить yt-dlp, когда YouTube в очередной раз сломает скачивание

Профиль браузера бота живёт отдельно, в
`%LOCALAPPDATA%\telemost-music-bot\chrome-profile`. Старую папку
`.chrome-profile` рядом с ботом, если она осталась, можно удалить.

## Качество звука

WebRTC по умолчанию кодирует микрофон в Opus на ~30 кбит/с моно — это речевой
режим. [RFC 7587](https://datatracker.ietf.org/doc/html/rfc7587) называет
комфортным диапазоном для полнополосной стереомузыки 64–128 кбит/с. Отсюда
жалобы «звук как с радио».

Бот правит это на лету. В `browser.py` вверху есть **`TARGET_KBPS = 128`**.
Как это работает:

- в SDP дописываются `stereo=1`, `sprop-stereo=1`, `maxaveragebitrate`
  и `usedtx=0` (иначе тихие места в музыке кодек принимает за паузу и вырезает);
- поднимается строка `b=AS`, если Телемост её выставил;
- отдельно ставится потолок битрейта у отправителя через `setParameters`.

Тонкость: по RFC `maxaveragebitrate` — параметр **приёмника**, он говорит
отправителю, сколько тому можно слать. Поэтому правится **входящий** SDP,
а не исходящий. Если правленый SDP отклоняется, бот молча откатывается
на оригинал — звонок важнее качества.

**Проверять командой `stats`.** Смотри строку «стерео» и битрейт. Если
потерь пакетов много — опусти `TARGET_KBPS` до 96 или 64.

### Тракт подачи звука

Всё от декодера до звуковой карты идёт в **float32** — целочисленного
округления нет ни на одном шаге.

- **Лимитер вместо обрезки.** `np.clip` рубит пики в квадрат, а квадратная
  волна — это гармоники по всему спектру, то есть хрип, на который кодек ещё
  и тратит биты. Здесь вместо этого плавно ведётся усиление, с упреждением
  в один блок (~21 мс): к моменту, когда громкий кусок дойдёт до карты,
  усиление уже опущено. Пока сигнал в пределах потолка, он проходит бит в бит.
  На замерах при перегрузе в 1.3 раза искажения 2.7% против 10.5% у обрезки.
- **Выравнивание громкости** (`loudnorm`, стандарт EBU R128, цель −14 LUFS).
  Треки перестают прыгать по уровню. Отключается командой `norm off`.
- **Буфер на ~4.7 с** между декодером и картой, старт после ~1.9 с
  накопления. Без него любая заминка сети или нагрузка от игры даёт щелчок.
  Если буфер всё же голодает, бот сообщит об этом после трека.
- **Приоритет процесса выше обычного** — чтобы звук не захлёбывался, пока
  идёт игра.

Что ещё влияет на чистоту звука:

- **наушники у всех.** Если кто-то сидит в колонках, его микрофон ловит
  музыку, его эхоподавление пытается её вычесть и в звонок улетает каша.
  Стоит ноль, а помех убирает много;
- **48000 Гц с обеих сторон VB-Cable** (и `CABLE Input`, и `CABLE Output`
  в дополнительных параметрах звука). При несовпадении ресемплит драйвер,
  а его ресемплер даёт треск;
- **не задирать `vol` выше 100** — пики обрезаются жёстко, это слышимый хрип.

В `browser.py` вверху есть настройка `BROWSER`. По умолчанию `"auto"` —
берёт первый установленный из Chrome, Edge, встроенного Chromium. Если Edge
капризничает, поставь `BROWSER = "chromium"`: встроенный браузер Playwright
не тащит корпоративные политики и ведёт себя предсказуемее.

## Как пересобрать portable-архив

На компьютере разработчика после обычного `setup.bat` запусти
`build_portable.bat`. Скрипт ставит закреплённые build-зависимости, скачивает
совместимый headed Chromium, собирает one-folder приложение и создаёт:

`dist\TelemostMusicBot-portable.zip`

Архив большой, потому что содержит собственные Python, Chromium и ffmpeg.
Результаты сборки находятся в `dist\` и Git их не отслеживает.
