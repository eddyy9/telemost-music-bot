# План v2: из терминала в десктоп-приложение

## Что должно получиться

Приложение — не пульт для бота, а **клиент Телемоста, внутри которого живёт бот**.
Слева список комнат как в Discord, справа звонок, внизу плеер. Бот — второй
участник того же звонка, с отдельной изолированной сессией.

```
┌─ Окно приложения ──────────────────────────────────┐
│ Комнаты   │ webview #1 — пользователь               │
│ # флудилка│   partition: persist:user               │
│ # катки   │   свой аккаунт, реальный микрофон       │
│ # музыка  │                                         │
│           │ webview #2 — бот (свёрнут)              │
│ ──────────│   partition: persist:bot                │
│ плеер     │   гость «Music Bot»                     │
│ ⏸ ⏭ 🔊    │   микрофон = MediaStreamDestination      │
│ ──────────│                                         │
│ громкости │ входящие потоки участников перехвачены, │
│ Макс 150% │ у каждого свой GainNode                 │
│ Илья  80% │                                         │
└───────────┴─────────────────────────────────────────┘
```

Ключевое следствие: раз пользователь слушает звонок через наше приложение,
громкость каждого участника (включая бота) регулируется локально.

## Разделение ответственности

| Слой | Что делает | Язык |
|---|---|---|
| Ядро | yt-dlp, ffmpeg, очередь, буфер, лимитер, позиции, история | Python (существующий `audio.py`) |
| Транспорт | локальный WebSocket на 127.0.0.1, случайный порт + токен | Python |
| Оболочка | окно, комнаты, два webview, кнопки, звуки | Electron |
| Инъекции | подмена getUserMedia, правка SDP, перехват входящих треков | preload-скрипты |

CLI не удаляется — остаётся вторым клиентом того же ядра и инструментом отладки.

## Этапы

### Этап 0 — страховка (сделано)
`.gitattributes`, тег `v1.0-cli`, bundle-бэкап в `_backup/`.

### Этап 1 — спайки (`docs/SPIKE-01.md`)
Три эксперимента, которые решают, что вообще можно строить.
**Результат этапа — выводы, а не код.**

### Этап 2 — ядро без интерфейса
`audio.py` обрастает WS-сервером. Команды те же, что в CLI. Второй режим
вывода: отдавать PCM в сокет вместо звуковой карты. CLI переписывается
в клиента ядра. Проверка: терминальная версия работает как раньше.

### Этап 3 — скелет Electron
Окно, список комнат (`rooms.json`), webview с Телемостом, кнопки плеера.
Автозаход переносится из `browser.py` (селекторы, `_looks_joined`, три попытки
загрузки, подмена User-Agent). Playwright удаляется из зависимостей.

### Этап 4 — звук без драйвера
Синтетический микрофон: WS -> AudioWorklet -> MediaStreamDestination ->
подменённый getUserMedia внутри webview бота. VB-Cable остаётся
переключателем в настройках как запасной путь.

### Этап 5 — личность бота
Изолированные partition, гостевое имя, страховки от подстановки имени
аккаунта, кнопка сброса. Яндекс.Музыка — третья partition.

### Этап 6 — громкость по участникам
Зависит от результата спайка 1.3. Перехват `ontrack`, GainNode на поток,
сопоставление потока с участником, хранение настроек локально.

### Этап 7 — сборка
Portable exe, мастер первого запуска, панель здоровья (переезд `diag.py` в UI).
VB-Cable **не бандлить**: donationware, включение в свой установщик требует
лицензии от VB-Audio. Только ссылка на официальный сайт + проверка хэша.

### Этап 8 — безопасность и полировка
`contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`,
`setPermissionRequestHandler` (микрофон только Телемосту), токен на WS,
запрет popup-ов из webview.

## Известные риски

| Риск | Проверяется | Если сбудется |
|---|---|---|
| Телемост не пускает Electron-клиент | спайк 1.1 | остаётся внешний браузер, Playwright не убираем |
| Синтетический микрофон не проходит | спайк 1.2 | VB-Cable становится основным путём, как сейчас |
| Звук участников микшируется на сервере | спайк 1.3 | пункт про громкость невыполним, убираем из плана |
| Яндекс меняет вёрстку | постоянно | автозаход и сейчас best-effort, UI показывает состояние |
| Два WebRTC-соединения с машины | этап 3 | свернуть webview бота, ограничить ему видео |
